# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is a personal macOS dotfiles / configuration management repo, not an application. It backs up and restores config for shells (fish/bash/zsh), dev tools (asdf, brew, git), editors/IDEs (Neovim, JetBrains), and macOS system settings, all driven by a modular `make` system. There is no build, lint, or test suite to run for code changes — validation happens via `make` dry-runs and targeted target invocations described below.

See `fish/CLAUDE.md` for detailed guidance specific to the Fish shell configuration (file structure, key bindings, functions). See `AGENTS.md` for a deeper maintenance/troubleshooting reference and `README.md` for user-facing docs — both are already comprehensive; don't duplicate their content here.

## Architecture

The Makefile system is split into focused modules, all included from the root `Makefile`:

- `Makefile` — entry point; defines shared variables (`HOME_DIR`, `CONFIG_DIR`, `JETBRAINS_DIR`, etc.) exported to sub-makefiles, and the `help` target.
- `makefiles/install.mk` — installation/restoration targets (`install`, `copy-configs`, per-tool `_copy-*` targets).
- `makefiles/backup.mk` — backup targets (`backup`, `backup-apps`, `backup-macos`, per-tool `_backup-*` targets, git sync via `backup-sync`).
- `makefiles/utils.mk` — maintenance targets (`status`, `clean`, `validate-config`, `dry-run`).
- `makefiles/dependencies.mk` — dependency checking (`check-deps`, `upgrade-deps`) and smart install ordering.

Each supported tool has a source directory at repo root (e.g. `fish/`, `nvim/`, `gitconfig/`) that mirrors its real target location (e.g. `~/.config/fish/`, `~/.gitconfig`). Adding a new tool means adding a matching pair of targets: `_backup-<tool>` in `backup.mk` and `_copy-<tool>` in `install.mk`, following the existing patterns (check source/target existence, use `rsync -a` for copying, quote paths, colored `echo` status output).

Target naming convention: no-prefix targets are public/user-facing (`backup`, `restore`, `install`); underscore-prefixed targets (`_backup-fish`, `_copy-nvim`) are internal implementation, invokable directly for testing a single component.

## Common Commands

```bash
make help              # List all available targets
make install           # Full install (update + copy-configs + brew + asdf + jetbrains + iterm2 + omf + env)
make install-minimal   # Essentials only: git, fish, nvim
make backup            # Full backup (apps + macOS settings)
make backup-sync       # Backup + git commit + push (requires main branch, pulls first)
make restore           # Restore all configs from this repo onto the machine
make status            # Show current configuration status
make check-deps        # Verify required tools are installed
make -n backup         # Dry run — show commands without executing
make _backup-fish      # Test a single backup target
make _copy-nvim        # Test a single install/copy target
```

## Working in this repo

- Most files under tool directories (e.g. `fish/`, `nvim/`, `karabiner/`) are periodically overwritten by `make backup` from the user's live `~/.config` — treat them as generated snapshots except where a sub-directory has its own `CLAUDE.md` documenting hand-maintained structure (e.g. `fish/`).
- Never commit real secrets: `env/home.env` and `.env` are backups of local environment variables; `.env.template` is the sanitized example checked into git.
- `macos/restore_macos_settings.sh` is auto-generated by `make backup-macos` — don't hand-edit it; change the generation logic in `makefiles/backup.mk` instead.
- A GitHub Actions workflow (`.github/workflows/`) validates Makefile syntax and target existence on push/PR to `main`/`master`/`develop` — keep `make --dry-run --just-print help` and `make --dry-run help` passing.
